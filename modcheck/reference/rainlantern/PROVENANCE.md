# Who wrote what in this project

This distinction is the point of the file. A complete mod hand-authored by
Claude is useful reference work; it is **not** evidence that ModCheck can
generate that mod, and nothing here should be read as if it were.

## Developer-authored (Claude, by hand, during this batch)

Every `.java` file under `src/`, every resource under `src/main/resources/`,
and every test under `src/test/`. Written against signatures retrieved from
the pinned toolchain with `modcheck lookup`, but composed by hand.

| File | What it is |
|---|---|
| `LanternCharge.java` | the charging rules, no Minecraft types |
| `ChargeCache.java` | what the client knows and for how long, no Minecraft types |
| `LanternBlock.java` | the block, its block entity and its ticker |
| `LanternBlockEntity.java` | one lantern's charge; load/save; the tick step |
| `LanternChargePayload.java` | the charge on the wire |
| `RainLanternNetwork.java` | type registration, recipients, send |
| `RainLanternContent.java` | block, item, block-entity type, gamerule |
| `Rainlantern.java` | main entrypoint — where registration is actually called |
| `client/RainLanternClient.java` | client entrypoint, receiver, disconnect clearing |
| `client/LanternHud.java` | viewed-lantern selection and HUD output |
| `src/test/**` | 40 JUnit tests |

## Deterministically generated by ModCheck

None of this project. An earlier batch generated five scaffolding classes for
this request into `build_workspaces/lantern` (gitignored); they wired
mechanisms and left the behaviour as marked seams. This project was started
from the scaffold's build files and manifest, and the generated classes were
replaced rather than filled in — the generated ticker, for instance, assumed a
level-scoped store, and this implementation uses a block entity.

`build.gradle`, `settings.gradle`, `gradle.properties` and the wrapper
properties come from `modcheck scaffold`, unmodified except for the JUnit test
source set added here by hand.

## Produced through an invoked coding agent

None. ModCheck has no model invocation, and no agent was invoked to produce
any of this. See `docs/AGENT_INTEGRATION.md` for the boundary that exists and
what is missing to cross it.

## Tests actually executed

40 JUnit tests, run by the project's own Gradle build on this machine with
Java 25.0.4.1 and Gradle 9.5.1. They exercise the charging rules, the
configuration bounds, per-lantern independence, the save/load contract, target
switching, and missing/stale client state.

They do **not** exercise anything that needs the game: whether Minecraft calls
`loadAdditional`, whether a packet arrives, whether text appears on screen.
Those are listed as unverified in `docs/RAIN_LANTERN_STATUS.md`.
